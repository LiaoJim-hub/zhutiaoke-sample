# 逐条可核 · 样例仓 / Per-Item Verifiable · Sample Repo（zhutiaoke-sample）

> **这个仓库里没有引擎，也没有判据集。**
> 只有：**一份样例报告**、**一份样例材料**、**一页双击就能算的复算页面**、**一份"改一个字就红"的对照**。
> 目的只有一个：**让你不必相信我们，就能自己核这份文件与它自称的指纹是否一致。**

---

## 一、它不解决什么（先读这一段）

- **它不判断内容对不对。** 它只判断"这份文件与它自带的指纹值是否一致"。
- **它不证明"没被改过"。** ★ 指纹内嵌在被校验的同一份文件里：改正文 → 重算 → 改写指纹行 ⇒ **照样一致**。要防"改完再重签"，必须用**外部锚**（见 §六）。
- **它不是认证。** 一致不等于合规、不等于合格、不等于监管认可。
- **它不背书。** 我们不出具人、不签字、不替你承担责任。
- **它不做排行。** 不存在分数、等级、名次。
- **它不是审计报告。** 样例报告**不供签署**，**不得用于对外质证 / 诉讼 / 向监管提交**——那一档须由具备资质的主体出具。
- **「未问」≠「通过」。** 材料里没呈现、或判据不适用的，记 **判不了（uncomputable）**，不记为绿。

> 一句话：**它能证明"字与签名对得上"，不能证明"话说得对"，也不能单独证明"没被改过"。**

## 二、30 秒上手

1. 下载或克隆本仓库；
2. **双击 `复算指纹.html`**（不联网、不装任何东西）；
3. 把 `样例报告·底稿三查.md` 拖进去；
4. 看到 **`PASS`** —— 文件内容与它自带的声称值一致；
5. 再拖 `样例报告·底稿三查·改一个字（FAIL 演示）.md`；
6. 看到 **`FAIL`** —— 那份报告的标题多了一个「？」。

不放心页面？**算法就写在 HTML 里**（纯 JS、无依赖、无压缩），你也可以用任何语言照 §四 自己算一遍。

## 三、这份样例怎么读（底稿三查）

样例对象是一份**合成**的审计工作底稿节选（某有限责任公司 2025 年度财务报表审计）。报告结论是 **2 红 + 1 判不了**：

| 判据 | 结论 | 红在哪 / 为什么判不了 |
|---|---|---|
| `wp_three_tables` | 红 | 三张表的**复核底稿均未见**（本判据查三张表；财政部该决定书**第六项**针对的是**合并现金流量表**这一张） |
| `wp_confirm_transit` | 红 | 函证**回函经被审计单位转交** ⇒ 回函可靠性未评估、证据链断裂（对应决定书**第八项**） |
| `wp_key_audit_matters` | **判不了（不适用）** | 材料同时含「底稿目录」与「报告节选」⇒ 该段是否本应存在无法判定；且主体为**非上市**有限责任公司，准则第 1504 号对关键审计事项段的强制要求针对上市实体 |

> 两条红的出处是**监管处罚认定**，不是我们编的规矩：
> 财政部《行政处罚决定书》**财监法〔2025〕371 号**（2025-12-29）。
> ★ 该决定书正文按「一、…八、」分项，本报告引用的项号即此口径（第六项、第八项）。

**只判这三条，不判更多。** 我们明确不判：底稿是否"编造"、合并抵销对不对、审计结论对不对——那要交叉验证物流/银行流水/两套数，或职业判断，**不是纯文本能判的**。报告「三、这份报告不做什么」逐条写了为什么。

**判据集本身不在本仓库。** 报告只给一个判据版本值（`workpaper:…`），**该值在本仓库无法复算**，仅用于产品内比对"是不是同一版判据跑的"。

**样例材料是合成的**（不是"真实底稿脱敏"）：事实要素取自上述公开决定书，主体已匿名化。**连样例都不假装是真的。**

## 四、可复算的算法（与报告内声明、与页面逐字一致）

```
1) 找到报告里「报告指纹」那一行；
2) 把该行 `sha256:` 之后的【前 16 位】十六进制字符清空（其余全文一个字都不动）；
3) 对剩余全文按 UTF-8 编码算 SHA-256；
4) 取前 16 位十六进制 ⇒ 这就是"实算指纹"；
5) 与报告声称的值比对：相同 ⇒ 一致，不同 ⇒ FAIL。
```

两个实现细节（**都会改变结果**）：

- **必须按字节读文件**，不要先做换行转换（CRLF ↔ LF）。页面用 `readAsArrayBuffer` 就是为了这个。
- **只清空"报告指纹"那一行**。报告里还有"材料指纹"和"判据版本"两处 `sha256:`，清错了就算不对。
- ★ **只清前 16 位**，不要"清掉全部连续十六进制"——否则遇到 32/64 位的值会与页面得出不同结果。

## 五、为什么"判不了"是一等公民

因为**误报比漏报更贵**：一份报告说"这条我判不了"，你还可以去问、去查；说"这条通过了"而其实没查，你就不会再查了。

所以我们坚持三态，而不是两态：

- **红**：材料里明确缺了 / 明确有反证；
- **绿**：材料里明确满足；
- **判不了（uncomputable）**：材料没呈现、判据不适用、或需要外部证据 —— **不折算成红，也不折算成绿**。

这份样例里第三条就是"判不了"。**它敢不敢说"判不了"，是这份样例最该被检验的地方。**

## 六、外部锚（为什么需要它，怎么用）

指纹自洽 ≠ 没被改过。真正的锚在**仓库之外**：

| 锚 | 值 |
|---|---|
| `样例报告·底稿三查.md` | **`sha256:e54c748c2dde58ca`** |
| `样例报告·底稿三查·改一个字（FAIL 演示）.md` | 声称 `e54c748c2dde58ca`，**应算得 `7a903e7cb4a6cb29`** |
| `样例材料·底稿三查.txt` | **`sha256:b893302442e76faa`** |

**怎么用**：拿**这张表的值**去核你手上的文件，而不是拿文件里的值核它自己。

**再加一道**：本仓库每次发布的 **tag / commit 哈希**也是锚——README 与文件若被同时改动，tag 会暴露。

**核材料**（证明"报告确实是对这份材料跑的"）：

```bash
# Windows
certutil -hashfile 样例材料·底稿三查.txt SHA256
# macOS / Linux
shasum -a 256 样例材料·底稿三查.txt
```
前 16 位应等于 `b893302442e76faa`。

> §四 那张"声称 / 实算"式的对照，演示的是**自洽性**，**不构成防篡改证明**。
